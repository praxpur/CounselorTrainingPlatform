# 账号与名单导入

正式登录使用学校导入的工号和初始密码。名单之外的工号不能自行注册；管理员与辅导员均须首次修改密码。
密码须为 12—128 个字符，每人使用独立初始密码，通过学校认可的渠道私下发放。服务端只保存带随机盐的 scrypt 哈希。

## 首个管理员

在服务器代码目录外准备受保护的 UTF-8 JSON 文件，内容为一个账号的数组：

```json
[
  {
    "id": "学校管理员工号",
    "name": "管理员姓名",
    "department": "学生工作处",
    "role": "admin",
    "initialPassword": "替换为单独生成的初始密码"
  }
]
```

工号仅允许字母、数字、下划线和连字符。不要将真实密码提交 Git、放入小程序包或粘贴到命令行。
在 `server` 目录执行，下例路径由学校运维人员指定：

```powershell
$env:DB_PATH = 'D:\学校数据\training.db'
node manage-users.js bootstrap 'D:\学校数据\首个管理员.json'
$env:NODE_ENV = 'production'
node server.js
```

已有管理员密码时 bootstrap 会拒绝再次初始化。新增管理员使用同样的 JSON 数组及 `import` 命令，可一次包含多个管理员和辅导员；不修改已有账号的角色。

```powershell
node manage-users.js import 'D:\学校数据\补充名单.json'
```

## 辅导员导入

管理工作台 → 用户名单管理 → 批量导入名单，选择 UTF-8 CSV 文件并检查预览后确认。
表头严格依次为：

```csv
工号,姓名,学院/部门,初始密码
```

在 Excel 中将工号列设为文本以保留前导零；CSV 有逗号或引号的字段须按标准加引号。每个文件最多 500 人、256 KB，前端每批提交 10 人；每批事务保证全部成功或全部失败。
若后续批次出错，前面已成功的账号保留，页面报告完成数。网络超时可能已经落库，请先搜索核对，勿盲目重复导入。
离线也可以执行 `node manage-users.js import <CSV路径>`；CSV 只创建辅导员，管理员须用 JSON 明确指定角色。

已有账号且已有密码会导致整批冲突，不会覆盖。历史测试名单只有在姓名、部门、角色完全一致、账号启用且尚未配置密码时才补设初始密码，保留历史活动记录。

## 密码重置与会话

正式环境只接受账号密码登录或成功改密签发的已验证会话。开发登录签发的 Token 不能在生产环境沿用，即使同一工号已经设置正式密码。升级前缺少验证标志的旧会话也须重新登录，不影响人员、活动或材料数据。
会话与验证标志在同一事务中创建；注销、到期清理和密码重置会连同标志撤销。登录和改密在取得数据库写锁后再次核对凭据和账号状态，避免覆盖刚发生的管理员重置。

用户名单管理可重置辅导员密码。重置会撤销其所有现有会话，并要求再次修改初始密码；停用账号不会因重置自动启用。
管理员密码遗失时，服务器运维人员在受保护 JSON 文件中填写 `id`、`initialPassword`，离线运行：

```powershell
node manage-users.js reset 'D:\学校数据\密码重置.json'
```

管理页不能创建、提权、停用或重置其他管理员；多管理员由持有服务器权限的运维人员管理。
正式环境保持 `NODE_ENV=production`，测试登录接口会强制关闭；请在 HTTPS 域名配置完成后使用。
登录与改密限制每账号 15 分钟最多 10 次尝试，连接来源 IP 同期最多 3000 次，全进程最多同时执行 4 次密码哈希。来源只取服务器 TCP 对端，不信任客户端自行填写的转发头；反向代理还需设置网络层限流。
完成导入后，按学校凭据管理要求移走或销毁含明文初始密码的源文件；不要把这些文件放进代码仓库或公开备份。
