# 签到与签退

活动管理 → 报名人员 → 开放签到 / 签退与查看现场记录。
管理员可分别开放签到、签退，选择扫码、定位或扫码＋定位；有效期从服务器当前时间起计算，为 1—240 分钟。
定位中心通过微信地图选择，允许范围 10—2000 米。前后端统一采用 GCJ-02 坐标。
辅导员报名后，从活动详情进入“活动签到 / 签退”。扫码使用相机；定位需在现场授权微信位置权限。

## 认定规则

- 未报名不能签到；签退前须先签到，活动开始前不能开放签退。
- 同一账号、活动和类型只能记录一次，重复请求返回冲突；时间由服务端记录。
- 二维码由服务端随机生成，绑定活动、签到类型及有效期，数据库只存哈希。刷新会使旧码立即失效；也可提前关闭。
- 定位方式服务端检查坐标、到中心的距离及设备报告的精度；扫码＋定位必须两项同时通过。
- 取消活动后无法继续签到或签退，历史现场记录保留。
- 签到和签退提供现场参加依据，**不会直接增加学时**。管理员仍按学校规则确认参加或审核经历；同一活动不重复计时。

二维码图像由服务端生成，管理页临时保存在微信私有目录并在离页时删除；不会公开发布带凭证的图片地址。
用户只能读取自己的现场记录；管理员可读取本活动全部记录。记录保留方法、服务器时间、定位距离与精度，不保存参与者原始经纬度轨迹。

## 微信接入与验收

代码已声明位置权限用途和 `getLocation`、`chooseLocation` 私有接口。
发布前需在微信公众平台核对当前账号类目是否允许申请这些接口，完成接口权限申请及隐私保护指引中相应的位置用途说明。
位置权限被拒绝、扫码取消、二维码过期、定位漂移等情况应在真实手机上验证。服务端测试与 SDK 模拟流程已覆盖，但不等同于真机或微信审核通过。

扫码无法独立阻止现场码被转发，客户端定位也无法独立防止设备伪造。若学校要求更强的参加核验，应使用双重验证并结合管理员现场确认。
生产域名与服务器尚未申请，先交付代码和部署模板；真实学校环境与真机验收保留为后续工作。

二维码生成使用锁定版本的 [node-qrcode](https://github.com/soldair/node-qrcode)。
