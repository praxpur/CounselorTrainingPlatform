# 自行培训与证明材料

辅导员从“活动记录 → 提交自行参加的培训活动”填写活动名称、主办方、参加日期、申请学时与培训经历，并上传 1—5 份材料。
参加日期不能在未来；学时直接填写，最多两位小数。管理员在统一经历审核页查看材料，填写认定学时并通过，或填写原因驳回。
待审、已通过记录不能由提交人修改；驳回后修改同一记录重新提交，保留记录编号，避免重提产生多份认定。

平台发布活动的经历仍在活动记录内提交，可附图片/PDF；认定学时始终采用管理员发布的活动学时，忽略客户端试图指定的认定数值。

## 学时与重复

自行培训只有审核通过后才计入个人年度/月度学时、年度排名及 Excel。管理员可认定与申请不同的学时；重复审核不会再次入账。
同一人的同日同名自行培训不能重复提交。已经报名的平台同日同名活动须走平台经历流程；反过来，已通过自行培训认定的同日同名活动不能再次通过平台确认计时。
这不是语义上的自动识别：名称不同但实际相同的活动，仍需管理员核对证明材料和历史记录，避免重复认定。
人员参加情况分别显示平台报名、确认、自行提交和自行通过次数，导出包含自行提交的活动明细。

## 文件边界与存储

- 支持 JPG、PNG、PDF，服务端按内容签名识别文件类型，不依赖文件名后缀。
- 每份不超过 5 MB，每次提交最多 5 份；每人最多 100 份、共 50 MB；同一服务进程最多同时接收 4 份文件。
- 文件先收齐验证，再以随机编号写入私有目录；超限立即返回 413 并关闭连接，上传中停用账号不留文件或元数据。
- 文件只允许所有者和已登录管理员下载；接口不公开静态文件目录，响应禁止缓存、禁止内容类型嗅探，并以附件方式交付。
- 文件绑定到经历或自行培训记录，不能引用他人的文件，也不能用于另一份提交。

`UPLOAD_DIR` 指定材料私有目录，默认 `server/uploads`（已在 Git 忽略规则内）。正式环境应把它放在代码目录之外，并与 SQLite 数据一起备份。禁止在 Nginx 中将材料目录设为公开静态目录。
单独删除数据库或只恢复文件都会破坏材料和记录的关联，恢复时必须使用对应备份。
已提交材料保留；未绑定文件会占配额，维护时应清理过期未使用文件。正式保留年限由学校规定后配置，不能任意删除审核证据。

开发验证使用独立内存数据库与测试私有临时目录，结束后清理。未使用真实学校材料；微信文件选择、文档预览和真机下载域名仍需发布前联调。
