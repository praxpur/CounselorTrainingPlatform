# 站内通知

当前实现小程序内的消息中心，不发送微信订阅消息、短信或邮件。首页和“我的”已接入消息入口，显示当前账号未读数；入口在页面显示时刷新并每 30 秒轮询，隐藏或卸载时停止。

通知包括：

- 新活动发布：发送给启用的辅导员；已报名活动调整：发送给仍有效报名的启用账号。
- 活动取消：通知该活动的历史报名人员，提醒取消活动不计学时。
- 报名成功、取消报名、重新报名，以及管理员确认参加的结果。
- 平台经历、自行培训的新提交或重提：提醒启用的管理员；审核结果只发送给提交人。
- 账号开通和管理员密码重置：保留账号本人的安全通知，不包含初始密码、密码哈希或会话凭证。

同一次确认参加同时批准待审经历时，只发送一条经历结果通知。活动取消或报名取消导致的系统驳回，不伪装成人工审核，也不会重复发送审核驳回消息。
停用账号无法读取消息；属于本人的安全、历史结果通知可保留，重新启用后再查看。公开发布与管理员待审提醒仅发送给启用的对应角色。

## 一致性与权限

通知由 SQLite 触发器在业务事务内写入。业务回滚不会留下消息；通知落库失败时对应业务变更也失败。每个源事件有一个批次编号，同批次对同一个人只保留一条消息；无变化的重复更新不生成新事件。
启动、升级或重建触发器不会追溯补发历史活动，也不会重复发送已有消息。
触发器更新在同一个 DDL 事务内完成，不产生跨进程重载时的发送空窗。

通知只能由当前会话的账号查询和标记已读，不接受外部指定的用户编号。管理员没有代读他人通知的接口。
点击通知先标记已读，再由后端根据当前角色和记录归属决定可打开的页面；记录失效或角色不匹配时不会返回无权访问的链接。前端也只接受固定业务页面。

## 分页与未读

消息中心每次 20 条，可只看未读、逐条打开或全部标为已读。重复标记已读不会再次写入。
列表首次读取返回当前账号的 `snapshot`，继续翻页携带该值，因此中途产生的新消息不会挤动原有分页。`hasNewer` 会提示刷新；手动刷新或重新筛选会建立新快照。
未读数始终表示该账号当前全部未读消息，不局限于已加载页。长列表采用现有的有界显示窗口及上一页入口。

## 接口集成

在当前业务表、取消报名字段初始化完成后，调用 `createNotifications(db)` 注册通知触发器。

| 路由 | 方法 | 模块调用 |
|---|---|---|
| `/api/notifications` | GET | `notifications.list(user, url)` |
| `/api/notifications/unread-count` | GET | `{ unreadCount: notifications.unreadCount(user) }` |
| `/api/notifications/:id/read` | POST | `notifications.read(user, id)` |
| `/api/notifications/read-all` | POST | `notifications.readAll(user)` |

接口已接入统一登录鉴权及初始密码修改限制之后；修改接口处理完请求体后会重新核验当前会话。
`read` 返回 `{ ok, changed, readAt, unreadCount, target }`；`target` 为 `{ url, tab }` 或 `null`。
列表使用既有 `limit/offset` 协议，并返回 `snapshot/hasNewer/unreadCount`。
客户端模块分别为 `pages/notifications/notifications` 和 `components/notification-entry/notification-entry`；消息中心已注册，消息入口只在已确认登录身份的区域显示。

消息随数据库备份保存，当前不自动删除；学校确定保留和归档规则后再安排维护，避免删除仍需追溯的通知。
