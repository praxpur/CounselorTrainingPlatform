# 操作审计

管理员从工作台“查看操作审计”进入，只读查询登录、数据变更、签到、审核、材料下载及数据导出记录。
支持按操作人工号、操作类型筛选，使用稳定游标加载较早记录。普通辅导员没有查询权限；HTTP 接口不提供删除或修改历史记录。

## 两类记录

1. 数据变更：SQLite 触发器在业务事务内保存变更前后值和操作者。覆盖人员、活动、报名与确认参加、平台经历、自行培训、密码凭据状态、会话、材料元数据、签到设置及签到记录。审计写入失败会使对应数据修改失败，不能出现业务修改成功而审计行未写入的情况。
2. 请求结果：保存登录成功/失败、密码修改、敏感写请求、材料下载、Excel 导出、审计访问及拒绝访问的结果。响应的 `X-Request-Id` 可与代理访问日志关联。

异步请求上下文将操作者和请求编号传入触发器，不依赖易串用的全局“当前管理员”。学校运维工具的离线操作记录为 `system`，同一进程执行共享一个运维请求编号。

## 记录边界

使用固定字段白名单，不记录密码、密码哈希、会话 Token/哈希、签到二维码凭据或证明材料内容。
人员姓名/部门、活动内容、经历、审核意见和材料文件名等必要业务前后值会进入审计表，只能由管理员查看。参与者的原始定位坐标不保存；签到记录只有距离与精度。
日志和业务记录保存在同一个 SQLite 数据库中，应随在线数据库备份一并保存，并限制数据库文件访问权限。

应用不会自动删除审计历史。学校明确保留年限与归档制度后，再配置相应维护流程；不得为了释放空间直接删除审核证据。
数据库持有者仍能绕过应用修改数据或删除触发器，当前方案不声称能抵抗拥有服务器或数据库权限的操作者。需要更强留痕时，可另行向学校的只追加日志系统归档。
直接用外部 SQLite 工具修改业务表会缺少应用注册的审计函数；人员导入、密码重置等操作应使用提供的运维工具。备份、完整性检查等只读操作不受影响。
