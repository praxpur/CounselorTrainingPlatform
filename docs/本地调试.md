# 本地调试

在项目根目录打开 PowerShell，首次使用先安装依赖：

```powershell
cd server
npm ci
```

## 配置与启动

使用 Node 22.16.0 或更新版本。在 `server` 目录准备配置文件；新下载项目时执行一次，已有 `.env` 时直接编辑，不要覆盖：

```powershell
Copy-Item .env.example .env
```

编辑 `server/.env`，当前本机配置如下：

```dotenv
NODE_ENV=development
HOST=10.29.182.131
PORT=3001
DB_PATH=../tmp/presentation-demo/training.db
UPLOAD_DIR=../tmp/presentation-demo/uploads
TRUST_PROXY=none
LISTEN_BACKLOG=2048
```

`DB_PATH` 和 `UPLOAD_DIR` 沿用现有测试数据；新下载项目不包含这些数据，需准备测试数据或指定新路径，并按[账号与名单导入](账号与名单导入.md)初始化管理员。相对路径基于启动时的工作目录，因此请始终在 `server` 目录启动；Windows 路径建议使用正斜杠，包含空格时用引号包住值。

每次启动只需执行：

```powershell
npm start
```

它等同于 `node --env-file=.env server.js`：Node 先读取配置到 `process.env`，再执行后端代码。缺少 `.env` 时会报错；修改配置后需按 Ctrl+C 停止并重新启动。保持窗口打开即可运行服务。

`.env` 是本机配置，已被 Git 忽略；仓库只保存 `.env.example` 示例。如果此前在当前 PowerShell 中使用 `$env:...` 设置了同名变量，它们会优先于文件值；请在新开的终端启动，或先用 `Remove-Item Env:变量名` 清除旧值。

生产配置模板为 `deploy/training.env.example`，正式服务器由 systemd 的 `EnvironmentFile` 加载，详见[部署与运维](部署与运维.md)。手动启动时也可指定正式配置：`node --env-file=/etc/counselor/training.env server.js`（在 `server` 目录执行）。

## 手机真机调试

1. 用 `ipconfig` 查看电脑当前 WLAN 的 IPv4 地址，将 `server/.env` 中的 `HOST` 改为该地址并重启后端；手机和电脑需要能互相访问。
2. 将 `utils/store.js` 中的 `API_BASE` 改为对应的 `http://电脑IP:3001`。当前值为 `http://10.29.182.131:3001`。
3. 在微信开发者工具打开项目，开发调试时关闭合法域名校验，重新编译并扫码真机调试；手机端也需开启相应的不校验选项。
4. 可先在手机浏览器访问 `http://电脑IP:3001/health`，正常返回 `{"ok":true}`。若无法访问，检查服务是否运行、Windows 防火墙及局域网设备隔离。

此 HTTP 配置仅供可信局域网调试，正式部署需要 HTTPS 和正式域名，参见[部署与运维](部署与运维.md)。
