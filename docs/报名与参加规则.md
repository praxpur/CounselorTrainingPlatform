# 报名、参加认定与历史记录

本页记录目前已确认并实现的系统规则。学校正式制度、证据保留期限和上线管理责任仍需由学校核对，不把系统默认值当作学校已经批准的制度。

## 报名与取消

- 以服务器保存的活动开始时间作为报名、取消报名的截止点；**活动开始前可自主取消，开始后不可自主取消**。
- 只能取消当前登录账号自己的报名，不接受请求体或查询参数指定其他工号。
- 活动已经取消、报名已经取消、没有报名或已经确认参加时，拒绝取消。
- 取消后立即释放容量；容量检查和报名写入在 SQLite 写事务内再次核对，重复或并发请求不会超卖。
- 同一活动仍开放报名且有空位时可以重新报名，复用原报名行，恢复当前状态。名额可能被其他人占用，重新报名不保留原有名额。
- 活动取消是管理员操作，与辅导员取消报名不同：管理员取消活动会保留报名及参加历史，但不再计入活动学时。
- 管理员可删除没有报名或参加记录的活动；已有记录的活动只能取消，以保留历史。

取消报名不物理删除报名行。`cancelled_at` 表示当前是否已取消；重新报名会将它清空，并保存新的报名时间。当前报名状态和最近一次报名时间保存在原报名行中；系统不再提供逐次操作审计。
同一活动的当前报名行只保留一份；历史报名活动数是去重后的活动数，不等于对同一活动反复报名的操作次数。
未取消报名的活动数、当前取消报名活动数和历史报名活动数分别显示，不能把已取消报名的人数计入活动容量。

取消时，该账号在此活动尚未审核的经历自动标为驳回并注明“报名已取消”，不保留认定学时。旧文字及材料仍保留；重新报名后可按参加后的流程再次提交。

## 参加和学时认定

报名本身不计学时。扫码、定位或双重验证签到/签退产生现场记录，不能绕过报名状态和有效期检查，也不会自行增加学时。
已取消报名的账号不能继续签到、签退或被管理员确认参加；活动取消后同样不能继续这些操作。平台活动无需辅导员提交经历。
管理员在活动开始后结合现场记录确认参加，系统采用管理员发布的活动学时。已确认参加后，不允许修改活动开始时间或活动学时。
同一活动只认定一次；平台活动与自行培训还会检查同人、同日、同名的重复认定，名称不同但实际同一活动仍需人工核对证明。
学时直接填写，最多两位小数，不按分钟或自然时长折算。

## 人员变更与证据保留

工号保存后不可修改；姓名和部门可由管理员修改。停用账号撤销会话并保留历史，不通过删除账号来处理人员离职或调动。
已报名活动取消、取消报名、账号停用均不删除其历史记录。已提交证明材料目前不自动按年限删除；学校确定保存期限后，由运维按批准的归档流程处理。
正式上线前应核对报名截止、参加认定依据、材料保留与归档要求，并在部署记录中留下负责部门和最终规则版本。
