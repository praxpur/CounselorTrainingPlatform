# 整体检查与优化记录（2026-11-11）

本轮检查覆盖小程序页面、前后端交互、身份与权限、数据库一致性、审核及学时、Excel 导出、字体打包、依赖安全和本机并发。检查不能证明所有潜在缺陷均已消除，也不构成正式上线验收。

## 已发现并修复

| 问题 | 修复 | 验证 |
| --- | --- | --- |
| 字体清单被小程序当成不存在的 `coverage.json.js`，导致白屏 | 改为生成并引用 `coverage.js`，保留 JSON 供构建使用 | 开发者工具已恢复学校品牌登录页；加入相对 require 检查 |
| 已保存工号可搭配任意姓名登录 | 核对保存的工号与姓名；停用账号仍被拒绝 | 错误姓名、停用、过期、生产环境关闭测试登录的接口测试 |
| `null`、数组等 JSON 请求可能导致内部错误；UTF-8 分片可能乱码 | 请求体仅接受对象，按字节限制 16 KB，收齐后解码 | 非法类型、超大中文请求体、汉字跨分片测试 |
| 等待请求体期间用户停用，后续写操作仍可能执行 | 完整接收请求体后再次核验会话 | 模拟分片提交期间停用用户，返回 401 且无写入 |
| 修改活动时读取的报名人数可能已经过期 | 接收完整修改请求后再读取当前活动状态 | 延迟修改请求与两人报名交错，降低容量被拒绝 |
| 直接确认参加后，关联经历仍停在待审；取消活动遗留不可通过的待审记录 | 使用事务同步确认与审核状态；取消时关闭待审经历 | 待审数量、经历状态及学时测试 |
| 不关联活动的旧经历无法处理 | 允许管理员驳回旧记录；仍禁止认定无活动依据的学时 | 无活动旧记录通过被拒绝、驳回成功的测试；已有历史数据保留 |
| 布尔值、无效日历日期可被宽松转换 | 更严格的字段类型、正整数及日期校验 | 非法数值、2 月 30 日、24:00 等边界测试 |
| 活动列表和排名存在重复逐条查询 | 活动列表批量关联本人状态与人数，排名用一次聚合查询；补充索引 | 原业务测试、年度导出及 500 并发请求测试 |
| 列表静默截断导致人员或活动不可见 | 去掉固定 500/1000 条截断；人员页增加搜索 | 1001 位新增内存测试用户完整返回；大型数据分页仍待完善 |
| 编辑页未加载完成时可能误发新活动；保存后返回失败可重复发布 | 加载完成前禁用表单，保存后防重复，返回失败回到管理页 | 前端编辑加载、错误时间及重复保存测试 |
| 断网和空数据混淆、旧年度数据可继续导出 | 统一加载/重试提示；年度加载时清空旧报告并禁用导出 | 断网恢复、快速换年和过期响应测试 |
| 导航返回触控区不稳定、首页按钮缺少处理函数 | 扩大为 44px 触控区域，返回失败回首页并补齐首页方法 | 开发者工具实际返回、导航组件测试 |
| textarea 默认 140 字截断、确认按钮状态不明确 | 显式长度上限、字段提示、按钮禁用样式；活动开始前不可确认 | 模板检查；需继续真机验证键盘与滚动 |
| 日期显示及编辑依赖手机时区 | 日期显示、编辑和统计统一采用北京时间 | 跨年与日期转换测试 |

## 测试与观察

- `npm test`：后端集成及前端流程共 8 个测试组通过，覆盖权限、报名容量、重复报名、审核、年度统计、本人数据隔离、Excel 回读、异常输入、竞态和加载状态等。
- `npm run test:load`：独立内存数据库、500 个预建立连接，同时请求活动列表、容量为 125 的报名、重复报名、个人年度统计。四阶段各 500 次请求均得到预期响应，实际报名恰好 125 条。
- 本轮该测试一次测量的 P95 分别为 305、226、170、175 毫秒。该数值只是本机单次观察，会随环境变化，不是性能承诺。
- `npm run test:load:cold`：500 个新 TCP 连接同时涌入时，本机 Windows 环境仍出现 `ECONNREFUSED`。保留失败结果，不将其解释成数据库已满足所有并发要求。
- 小程序 require、脚本语法、页面注册、WXML 标签和图片引用已检查；实际字体导入导致的白屏已在开发者工具中确认修复。
- 本轮先遇到过期会话，用户随后自行登录管理员。已在开发者工具中检查工作台、活动列表、独立发布表单及空表单必填提示、年度排名、年份滚轮打开与取消、返回导航、人员搜索与恢复、待审批页面和空状态；未提交测试活动或修改审批记录。其余检查以本记录中的实际验证为准；前端模拟测试不能代替真机测试。工具仍提示灰度基础库与预加载警告，需在正式基库及真机中继续核对。
- 实际开发数据库只读检查：完整性为 `ok`，外键错误、待审/已确认冲突和无效活动起止时间均为 0。自动化测试使用独立内存数据库，未对实际活动和报名数据做测试性增删。

## 尚未满足的正式上线条件

1. 当前仍为开发测试登录，不在名单内的测试工号仍可首次创建账号；姓名与工号是弱身份凭据。`NODE_ENV=production` 下测试入口关闭，正式认证尚未实现。学校已决定不接统一门户，后续需据此落实正式名单核验和管理员身份保护。
2. 学校服务器、HTTPS 域名、备份/恢复、监控、完整操作审计、限流以及正式数据库部署尚未联调。
3. 冷连接突发和磁盘数据库下的 500 人负载，需要在目标学校环境验收；本机内存测试不能替代。
4. 大数据量前端分页、批量名单导入、附件上传和消息通知不属于当前已完成能力。
5. 真机上仍需检查字体加载、键盘、日期滚轮、长文本、小屏幕、网络切换，以及 Excel 的打开、保存、分享。
